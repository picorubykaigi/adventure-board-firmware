# LED マトリクス シミュレータ

ブラウザで **実機と同じ `IS31FL3729` ドライバ**を動かし、16×16 の光り方を目で見る。
基板が無い間の検証手段であり、そのまま教材にもなる。

## 使い方

```console
rake sim:server
# → http://localhost:8080/sim/ を開く
```

リポジトリのルートをサーバのルートにしている。
ページが `mrbgems/picoruby-is31fl3729/mrblib/is31fl3729.rb` を
**コピーではなく実ファイルとして**読むため。

右のテキストエリアに Ruby を書いて Run。左の基板の絵に結果が出る。

最初に開くサンプルは URL で選べる: `?example=` に一覧の値を付ける（`?example=03_draw.rb`、
実機専用なら `?example=device:oled.rb`）。一覧に無い値なら先頭のサンプルを開く。

| ボタン | すること |
|---|---|
| サンプルの一覧 | `sim/examples/` のサンプルと、その下に「実機専用（シミュレータでは動かない）」として `examples/` のもの。実機専用のものは、読み込んだままのコードで Run を押しても走らせず、「実機で実行」を案内する（書き換えてあれば走らせる） |
| **Run** | 前に走らせていたコードを止め、欄のコードを新しいタスクで走らせる。**音もここで有効になる**（ブラウザはクリックの中でしか音を出させてくれないので、必ず押されるこのボタンに持たせた）。基板の状態はそのまま引き継ぐ |
| 文字の大きさ（コードの欄の右上。小・中・大） | コードの欄・ライブラリのコード・鳴った音・実機の端末の文字の大きさ。ブラウザが覚えておく |
| **シミュレータをリセット** | 画面の中の基板の電源を入れ直すのに当たる（実機には何もしない）。コードを止め、仮想の LED ドライバ 2 個・GPIO・割り込みの登録を初期状態に戻し、ボードレイヤ（`$board`）を作り直す。欄のコードと明るさのスライダーはそのまま |
| ▸ 鳴った音を見る（欄の下の小さな文字） | MML などが出した音の記録（ノートログ）を出す。音が出せない環境でも、何がいつ鳴ったかはここで分かる |
| ▸ ライブラリのコードを見る（同じく欄の下） | サンプルが呼んでいるボードレイヤ（`lib/adventure_board.rb` と `lib/adventure_board/`）を色付きで表示する。読むだけ。ページが実際に動かしているもの、実機の `/lib` に入るものと同じ |

Run が基板を作り直さないのは実機と同じにするため。実機のシェルで別のスクリプトを流しても、LED ドライバのレジスタや
割り込みの登録は前のまま残る。LED ドライバを直接いじって（たとえば `reset` して）おかしくなったあとは、「シミュレータをリセット」を押さないと
次のサンプルが半分しか光らない — 実機で `tools/r2p2dev.py reset` を挟むのと同じ。

```ruby
matrix = AdventureBoard.matrix
matrix.clear
matrix.set(3, 5)        # x, y は 1..16
matrix.set(4, 5, 0x40)  # 3 番目の引数は明るさ (0..255)。見た目に比例するよう補正される
matrix.show             # これを呼ぶまでチップには届かない
```

**書き方は実機とまったく同じ。** シミュレータ専用の構文は無い。
サンプルの先頭にある `require 'adventure_board'` は実機で必要なもので、
ブラウザでは（ソースが連結済みなので）何もしない。
繰り返しは `while true` + `sleep_ms` で書く。ブラウザではこのコードが
専用のタスクで走り、`sleep_ms` のあいだ画面に制御が戻るので固まらない。

```ruby
while true
  matrix.clear
  matrix.set(x, y)
  matrix.show
  sleep_ms 60
end
```

canvas は 50ms ごとに仮想チップの中身を映しているので、
「画面を更新しろ」と書く必要はない（実機のパネルが常時スキャンされているのと同じ）。

`matrix.top` / `matrix.bottom` で `IS31FL3729` を直接触れる。
`AdventureBoard.board.i2c` は LED ドライバのバス（ここでは仮想、実機では I2C0）。

**シミュレータ専用の構文はありません。** `AdventureBoard.matrix` / `.buttons` /
`.speaker` / `.status_led` はすべて `lib/adventure_board.rb` — 実機にも載るボードレイヤ — が
定義しています。ここで書いたサンプルはそのまま基板で動きます。
違うのは起動時にペリフェラルを組む部分だけで、それはサンプルの外にあります。

## 実機で実行

ボタンは 2 つの枠に分けてある。「シミュレータ」の枠は画面の中の基板に、「実機（USB）」の枠は USB の先の基板に効く。

| 実機のボタン | すること |
|---|---|
| 実機に接続 / 切断 | ブラウザのポート選択を出してつなぐ。R2P2 は CDC を 3 本（シェル / デバッグ / MIDI）出すので、**最後に接続されたもの（一覧の末尾）**を選ぶ。COM 番号の若いほうではない |
| 実機で実行 | 走っているものを Ctrl-C で止め、欄のコードを `/home/run.rb` に書いて実行する。その場で走るだけで、再起動しても走らない |
| 実機の app.rb にする | 欄のコードを `/home/app.rb` に書いて実行する。**電源を入れるたびに動く**、基板の「作品」にする（R2P2 は起動のたびに `/home/app.rb` を実行する。PC なしで動かすための仕組み） |
| 実機を再起動 | Ctrl-C のあとシェルの `reboot`（ウォッチドッグによる再起動。周辺回路も電源投入時の状態に戻る）。電源の入れ直しと同じで、`app.rb` があればそれが走る |
| 実機の app.rb を空にする | Ctrl-C のあと `/home/app.rb` を何もしない 1 行に書き換える。作品をやめて、電源を入れるとプロンプトで止まる基板に戻す |
| ライブラリを最新にする | ページのいちばん下の「▸ 高度な機能（実機用）」の中。基板の `/lib` をこのページの `lib/`（`SimApp::LIB_FILES`）にそろえる。1 本ずつ読んで比べ、違うものだけ `<パス>.new` に書いてから `mv` で入れ替え、同じ名前の `.mrb` を消して再起動する。全部同じなら何もしない。書く途中で失敗したら `.new` を消して元のまま。量産基板のファームを焼き直さずにライブラリの修正を届けるためのもの（[dev-docs/webserial-console/file-transfer-plan.md](../dev-docs/webserial-console/file-transfer-plan.md)）。偽の基板での確認は `tools/browser-check/lib-update-check.cjs` |
| .mrb にして実機で実行 / 実機の app.mrb にする | 「▸ 高度な機能（実機用）」の中。コードの欄をページでコンパイルし（`PicoRubyVM::InstructionSequence.compile(src).to_binary`）、`/home/run.mrb` に送って動かす / `/home/app.mrb` に書く。実機の上でコンパイルしないので、その分のメモリが要らない。R2P2 は `app.mrb` を `app.rb` より先に動かすので、［実機の app.rb にする］と［実機の app.rb を空にする］は `app.mrb` があれば消す |
| 対戦ゲームを実機の app.mrb にする | 「▸ 高度な機能（実機用）」のいちばん下。`games/link_pong.mrb` があるときだけ出る。それを実機の `/home/app.mrb` に送る。下の「対戦ゲーム」 |
| ライブラリを初期設定に戻す | ページのいちばん下の「▸ 高度な機能（実機用）」の中。基板の `/lib` に残った `.new` と `.mrb` を消し、`/etc/adventure-board-files`（ファームが書いた印）を消して再起動する。起動するときにファームが、自分の版のライブラリを書き直す。`/home` には触らない |

**「実機の端末」は本物の端末（xterm.js）。** つないだあとはそこに打てば R2P2 のシェルがそのまま使える（`ls` `free` `irb` `vim` …）。
基板の出力は stock の `JS::WebSerial#start_terminal_read` が JS 側で直接端末に流し、Ruby 側は「実機で実行」などのあいだだけ
横から覗く（プロンプト待ちは `capture_*`、PicoModem のフレームは `binary_capture_*`。PicoRuby の Web コンソール
`picoruby-wasm/demo/www/terminal.html` と同じ作り）。ページが基板と話しているあいだ、打鍵は捨てられる。
端末にフォーカスがあるあいだ、矢印キー / Z / X はシミュレータのボタンにならない。下辺をドラッグすると高さを変えられる。
ページ自身が書く行は `[接続] …` と薄い色で出る。

再起動すると USB が一度切れる。**一度許可したポートはブラウザがクリックなしで開き直せる**ので、基板が戻ってくると自動でつなぎ直す
（ケーブルの挿し直しでも同じ。「実機を切断」を押したあとはつなぎ直さない）。仕組みは stock の `JS::WebSerial` が持っている
`_watch_connect_events` / `_take_last_connected_port`。戻ってくる途中の基板には何も送らない（起動中の R2P2 はキー入力を待っているため）。

同じエディタのコードを、USB でつないだ基板に送って動かせる（Chrome / Edge のみ）。

1. 基板の USB シリアルを **Windows 側に置く**。WSL に渡している（`usbipd attach`）と、
   ブラウザのポート一覧に出ない。`usbipd detach --busid <BUSID>` で戻す
2. **[実機に接続]** → ポート選択で R2P2 の COM ポートを選ぶ。3 本出るので、
   プロンプト（`$>`）が端末に出るものが正解
3. **[実機で実行]** — 次を順に行う:
   1. Ctrl-C で実行中のプログラムを止め、プロンプトを待つ
   2. Ctrl-B でシェルのファイル転送（PicoModem）に入り、エディタの内容を
      `/home/run.rb` として送る。512 バイトごとに受信確認、最後に CRC32 を照合
   3. シェルに `/home/run.rb` を送って実行する

実機モードではパネルとボタンは使わない。LED は基板で光り、ボタンも基板のものを押す。
実機そのものはヘッドレスのブラウザでは扱えないが、偽の基板を相手にした一通りは
`tools/browser-check/reconnect-check.cjs` で確かめられる。

`/home/run.rb` は R2P2 が勝手に走らせることはない。**電源を入れるたびに動かしたい**ものは
[実機の app.rb にする] で `/home/app.rb` に書く（R2P2 は起動のたびにこれを実行する）。
以前は [実機で実行] が `app.rb` に書いていたので、試しに流したものが次の起動から毎回動いていた。

「何度も実行していると実機が応答しなくなる」件（2026-09-14）は、PSG が core1 で動いているあいだに
フラッシュへ書くと core1 が固まるのが原因だった。2026-09-21 に修正
（[../dev-docs/upstream-issues.md](../dev-docs/upstream-issues.md) の 4）。
音を使わないスクリプトでも起きるなら別の原因なので、記録すること。

## 基板の絵とブレッドボード

左は KiCad で描いた基板（量産版 V1）の絵で、LED マトリクス・ボタン・ステータス LED・ブレッドボードに挿した部品が、
実物と同じ位置に重なる。上のタブで「基板全体」「LED マトリクス」「ブレッドボード」を切り替える
（LED マトリクスやブレッドボードを押しても大きくなる）。

ブレッドボードを大きくすると、部品の棚が出る。部品を選んで穴を押す。
中でつながっている 5 穴（溝の上の a〜e、下の f〜j、列ごと）は薄い線で結んである。部品を挿している途中は、
待っている足の穴の 5 穴が黄色くなる（その列のどこに挿しても同じ）。
「動かす・押す」のときは、足の挿さった穴を押すとその足が持ち上がり、次に押した穴に挿し直せる（反対の足は挿したまま。
同じ穴を押すとやめる）。ジャンパ線・抵抗・LED の足に使える。スイッチは「外す」で外して挿し直す。

| 部品 | 挿し方 |
|---|---|
| ジャンパ線 | 端を 2 か所。J1 の穴も使える |
| 抵抗 1kΩ | 足を 2 か所（セットは 2 本。何本でも置ける） |
| 青 LED | 長い足（＋、アノード）、短い足（−、カソード）の順。逆に挿すと光らない。挿した穴に赤い ＋ と黒い − の印が付く |
| タクトスイッチ | e の段を 1 か所。溝をまたいで e・f の 2 列に 4 本の足が挿さる。**溝をはさんだ足どうしは最初からつながっていて**、押すと左右の列がつながる（実物と同じ） |

J1 の GPIO は、コードからは実機と同じに見える。`GPIO.new(2, GPIO::OUT).write(1)` で GPIO2 の先の LED が光り、
スイッチの先の `GPIO.new(3, GPIO::IN | GPIO::PULL_UP).read` は押すと 0 になる。`irq` も立つ。
何もつながっていない入力は宙に浮いていて、読むたびに値が変わる。

回路は本当に計算している（`sim_circuit.rb`）。各点の電圧を連立方程式で解き、LED は電流と電圧の曲線どおりに扱う。
LED は青（1 mA で 2.7 V、20 mA で 3.0 V）。3.3 V の GPIO からだと抵抗に残る電圧が小さいので、電流は小さい。
明るさは電流に比例する: 抵抗 1 本で 0.62 mA、直列 2 本で 0.35 mA（半分より少し多い）、並列 2 本で 1.08 mA。
次のときは、絵の下に警告が出る。

- GPIO から 12 mA を超えて流れる（抵抗を入れ忘れた LED など）
- LED に 20 mA を超えて流れる。4 mA を超えたら、抵抗の入れ忘れとして注意する
  （青 LED を GPIO に直につなぐと約 8 mA で、GPIO と LED のどちらの上限にも届かないため）
- 3V3・5V が GND とつながっている
- GPIO に 3.6 V を超える電圧がかかっている（5V を入れたなど）

配線は「▸ 配線を文字で見る・貼り付ける」で文字にできる。1 行 1 部品で、貼り付けて「この配線にする」で戻せる。

```text
wire J1-5 a3        ジャンパ線（J1-5 は GPIO2）
resistor b3 b7      1kΩ
led c7 c9           アノードが先
wire J1-3 d9        J1-3 は GND
switch e11          足は e11 e13 f11 f13
```

サンプルのコメントに同じ形で配線を書いておくと、ページはそのサンプルを読み込んだときにその配線にする
（`sim/examples/07_breadboard_led.rb` の「# 配線:」）。実機ではただのコメントなので、シミュレータ専用の構文にはならず、
実物を配線する人の手順書にもなる。穴のあとに書いたものは説明として読み飛ばす。

配線はブラウザに覚えさせてあり、ページを開き直すと戻る（見ている人ごと。ほかの人とは共有されない）。
「シミュレータをリセット」は、ピンの設定だけを戻し、挿した部品はそのまま残す。

### 基板の絵の作り方

`sim/board/board.webp` と、位置の表 `sim/board_layout.rb` は、基板リポジトリの `.kicad_pcb` から作る。

```console
rake sim:board_art                      # 既定は tmp/picorubykaigi01-board（BOARD_DIR で変えられる）
```

KiCad の 3D モデル入りイメージ（`kicad/kicad:9.0-full`、約 5GB）の中で、上から見た絵を描き、切り抜き、
LED マトリクス・ブレッドボード・J1・ボタンの位置を書き出す（`tools/board-art/build.py`）。基板の clone には書き込まない。

- 描画は `--quality basic`。`high` だと、ブレッドボードのまわりに暗い影が出る
- 基板データにはレジストとシルクの色が無いので、描くための写しの中で緑と白を入れている
- U1（RP2350）のモデルは KiCad 5 の書き方（`${KISYS3DMOD}/….wrl`）で、KiCad 9 では見つからない。写しの中だけ `.step` に差し替える
- LED マトリクスの LED の部品の形には 3D モデルが無いので、写しの中で KiCad 標準の 0402 LED を付ける。白い本体が点いて見えるので、描いたあと基板の緑に寄せている（`tint_matrix_leds`）

## コードの色付け

コードの欄は構文で色が付く。解析は自前の字句解析ではなく、**PicoRuby のコンパイラが持っている Prism**
（Ruby の構文解析器）に任せている。`mrbgems/picoruby-syntax-highlight` の `SyntaxHighlight.tokenize(source)` が、
ソースの 1 バイトごとに 0〜8 の分類（キーワード・文字列・コメント・数値・シンボル・定数・`@` `$` の変数・メソッド名）を返す。
構文エラーの途中でも表は返るので、打っている最中も色が付く。

- 描画は「テキストエリアの下に、同じ文字を色付きで並べた `<pre>` を敷き、テキストエリアの文字を透明にする」方式。
  入力・選択・IME はテキストエリアのまま。2 枚の行の位置がずれないように、**行は折り返さない**
- Ruby 側（`CodeColors`、`sim_app.rb`）が分類の切れ目ごとに `<span class="kN">` を作り、`setCodeColors`（`index.html`）に渡す。
  ハートビートで欄の文字列を見て、**前に色を付けた文字列と違うときだけ**解析する（打鍵・貼り付け・サンプルの読み込みを区別しなくて済む）
- 色は `index.html` の `.k1`〜`.k8`。分類 8（メソッド名）は演算子や `[` `]` にも付くので控えめな色にしてある
- 公開（GitHub Pages に自動で出す）は、リポジトリを別の Organization に移してから。それまでは各自の環境で組む
- **`rake sim:wasm` で作った wasm が要る。** stock のパッケージ（CDN）には `SyntaxHighlight` が無く、そのときは色なしの今までどおりの欄になる
- `rake sim:check` は各サンプルで「色が付いているか・下の文字と欄の文字が一致するか・分類ごとの個数」を 1 行で報告する。
  見た目は `tools/browser-check/editor-shot.cjs`（欄をスクロールした絵を `tmp/browser-check/editor-colours.png` に出し、2 枚の位置と大きさを数字で出す）

## 何を再現しているか

仮想チップは、ドライバが実際に書くレジスタをデコードする。

- アドレス自動インクリメント（ドライバの一括転送が前提にしている）
- PWM レジスタ 0x01〜（`(sw-1)*0x10 + cs`）
- `SSD` ビット（0 なら全消灯）
- `GCC`(0xA1) と Scaling(0x90〜0x9F) — **電源投入時は両方 0 なので光らない**
- Reset (0xCF ← 0xAE) で全レジスタが POR に戻る

輝度は `pwm/255 × gcc/64 × scaling/255`。実機の見え方の近似で、
光学的な正確さは狙っていない。

## 座標

上半分（y = 1..8）が U10 (0x34)、下半分（y = 9..16）が U11 (0x35)。
**U11 は列が左右反転して配線されている**ので、`cs = 17 - x` になる。
根拠は `dev-docs/led-matrix-gem/hardware.md` §4（r1 の netlist から導出）。

上下・左右のどちら向きが物理的な「上」「左」かは、実機で 1 ドット点灯するまで未確定。

## やっていないこと

フォント描画（`picoruby-shinonome`）と VRAM の描画 API。
どちらも C 拡張で、stock の `@picoruby/wasm-wasi` には入っていない。
`dev-docs/wasm-simulator/README.md` の Stage 2 で、
emsdk を入れて自前ビルドすれば通せる。

## 対戦ゲーム（games/link_pong.mrb）

コンソールの［対戦ゲームを実機の app.mrb にする］が、`sim/games/link_pong.mrb` を実機の `/home/app.mrb` に送る（ファイルがあるときだけボタンが出る）。
ライブラリを `require` すると実機のメモリが足りないので、**ゲームと、使うライブラリの部品をまとめて 1 本の .mrb にしたもの**を置く。
`sim/` の中なので、公開するコンソールにもそのまま入る（`rake site:console_standalone`）。実機の `/home/examples` には入らない。

- 中で `require 'adventure_board'` を呼ばない（呼ぶと実機の `/lib` を読んでコンパイルし、まとめた意味がなくなる）
- 実機のファームと同じコンパイラで作る（`RITE0400`）。コンソールは、先頭の版がページのコンパイラと違えば送らない
- 中に入れたライブラリはその時点のもので固まる。`lib/` を直したら作り直す
- 作り方の例: `docker compose -f docker/compose.yml run --rm shell bash -lc "rake && build/host/bin/mrbc -o sim/games/link_pong.mrb ゲーム.rb"`
- **まだ置いていない**（別にコミットされる予定）。無いあいだはボタンが出ない。

- 偽の基板での確認（`tools/browser-check/lib-update-check.cjs`）は、`hello_game.mrb` をこの名前でページに渡し、届いたものを 1 バイトずつ比べる
